### 2.3 InMemoryScBusPort — dispatch logic to replicate in NatsScBusPort

The in-memory port dispatches by `envelope.routingKey().topic()` as map key.
For NATS, the equivalent is the physical subject derived from that topic.
The NatsScBusPort must:

1. Accept registration by logical `topicOrRoute` string.
2. On publish: derive the physical NATS subject, publish the serialized wire envelope.
3. On subscribe: bind a NATS subscription to the physical subject, deserialize, invoke handler.

The `dispatchRecordId` and `attemptId` are generated by `RuntimeDispatchService`
via `DispatchStateWritePort`, not by the port itself. `NatsScBusPort` must return a
`DispatchOutcome` — `Dispatched` on NATS publish success, `Failed` on NATS error.
NATS publish acknowledgment (JetStream ack) is transport confirmation only — it must
NOT be treated as semantic execution success.

### 2.7 Architecture test — pomHasNoBrokerDependency (ACTION-MIR-B-001)

Current forbidden list (confirmed):

```java
List<String> forbidden = List.of(
    "io.nats", "jetstream", "lettuce", "vertx", "grpc-netty",
    "kafka-clients", "amqp-client", "mqtt");
```

**`io.nats` is in the forbidden list.** When MIR-B adds `io.nats:jnats` to pom.xml,
this test fails. The update must happen in the SAME COMMIT as adding the dependency.

Update strategy — remove `io.nats` from forbidden and add a dedicated test:

```java
@Test
void pomContainsIntentionalNatsBinding() throws Exception {
    // NATS is the intentional SC-B binding — its presence is required
    String pom = Files.readString(Path.of("pom.xml"));
    assertThat(pom).contains("io.nats");
    // No other broker may be present
    for (String unexpected : List.of("lettuce", "vertx", "grpc-netty",
            "kafka-clients", "amqp-client", "mqtt")) {
        assertThat(pom.toLowerCase()).doesNotContain(unexpected);
    }
}
```

And remove `"io.nats"` from the existing forbidden list.

### 2.8 NatsSubjectBuilder — must be created

No subject builder exists. Per SDD-SOV-SC-B-NATS-CORE-JETSTREAM-001, physical
subjects are derived from `ScRoutingKey`:

```text
Command subject:
  sc.v1.{scid1(habitatId)}.{scid1(adapterId)}.command.{topic-token}

Event subject:
  sc.v1.{scid1(habitatId)}.event.{topic-token}

Response subject:
  sc.v1.{scid1(habitatId)}.{scid1(adapterId)}.response.{topic-token}.{correlationHex}

Lifecycle subject (announce):
  sc.v1.{scid1(habitatId)}.lifecycle.announce
```

Where `scid1()` = `ScSubjectIdTokenCodec.encodeScid1()` and
`correlationHex` = `ScCorrelationTokenCodec.encode()`.

`NatsSubjectBuilder` is a pure utility — no broker dependency, fully testable.
It can be introduced in `bus.nats` before `NatsScBusPort` exists.
